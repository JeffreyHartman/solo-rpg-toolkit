# AI GM harness survey

Date: 2026-11-25

Question: what can existing AI game-master harnesses and solo-play tools teach a
browser-based solo RPG harness? The harness has a Python engine that owns state and
dice, an AI Referee that acts only through engine tools and proposes procedures as
cards, an "available actions" list shown as map and buttons, and Ruleset, Generator
and Module plugins. The first target is a FlexTale prepless dungeon on OSE rules.

Scope: 16 tools and 5 papers. Each claim has a source link. "Unverified" marks a claim
that I could not trace to a primary source. GitHub star counts come from the GitHub API
on 2026-11-25.

## Top takeaways for this harness

1. **Every serious open project puts numbers in code and fiction in the model.**
   Project Infinity says "the engine is authoritative" and that nothing in its mechanics
   panel "is generated by the model" [PI-README] [PI-HOW]. Loreweaver says "the one that
   owns the numbers is not a model" [LW]. rpg-mcp calls itself a backend "that turns any
   LLM into a game master who can't cheat" [MCP]. Research agrees. A fine-tuned state
   tracker reached only 58% joint accuracy, and the authors say full tracking "may require
   additional machinery beyond a finetuned LLM" [DND-DIALOG]. Your engine-owns-state
   decision matches the field.

2. **The opposite path exists, and it tells you where code feels bad.** Friends & Fables
   moved combat from code to an AI agent with tools in Combat V4. The team said code-driven
   combat felt "rigid and frustrating" [FF-COMBAT4]. They still enforce spell slots in code,
   and they warn that Franz will "get things wrong here and there". Lesson: let the AI pick
   *which* procedure applies (your proposal card). Keep the *resolution* in the engine. Make
   the procedure list wide enough that the AI rarely has nothing to propose.

3. **The model will not do bookkeeping on its own. Plan a second pass.** Loreweaver reports
   that a strong model "ran an entire module without once updating the game's state". They
   added a small "Scribe" model that compares the ledger to the narration and *proposes*
   fixes. The engine checks the numbers [LW]. Project Infinity has the engine re-ask the
   model when a turn ends with no prose or no place declaration [PI-HOW]. For you: when a
   rules event should happen (mark progress, tick a clock, spend a torch), the engine or a
   checker should raise it as a card. Do not trust the Referee to remember.

4. **The engine should write the mechanics text, not the model.** Project Infinity appends
   an engine-written "Mechanics panel" after the prose [PI-HOW]. Iron Vault stores each move
   as a structured `iron-vault-mechanics` block in the journal and renders it as a card
   [IV-MECH]. Show a resolved card (roll, result, state change) next to the narration. The
   player can then see the ruling without reading prose.

5. **Rolling summaries degrade play. Keep a verbatim log and retrieve from it.** AI Dungeon
   users switch off auto-summary: "It's an AI summarizing an AI and feeding that back into
   the AI" [AID-REDDIT]. Friends & Fables replaced its memory summary with a short "plot"
   plus searchable long-term memories [FF-FRANZ2] [FF-MEM2]. Narrative Engine archives
   every turn verbatim and injects retrieved scenes verbatim: "Nothing is summarised away"
   [NE]. Your best defence: the engine state *is* the memory. Inject a lean state sheet
   each turn, keep the last N turns verbatim, and search an append-only event log for
   older detail.

6. **Show the player what the AI sees, and give each kind of context a budget.** AI Dungeon
   splits leftover context into fixed shares (about 25% cards, 50% history, 25% memories)
   [AID-CONTEXT]. Users complain that triggered cards then do not load [AID-REDDIT].
   Friends & Fables shows a "working context" drawer above the input. Blocks are Active,
   Idle or Archived, and each group has an adjustable budget [FF-FRANZ2]. Narrative Engine
   shows a live token gauge [NE]. A small "Referee context" drawer would make bad rulings
   debuggable.

7. **Fewer, broader tools. Return deltas, not snapshots.** rpg-mcp cut 195 tools to 36 and
   cut tool overhead from about 50K to 6-8K tokens [MCP]. Project Infinity returns only the
   *delta* of a state change and keeps the full result in a UI toggle. A build gate holds the
   fixed prompt under a token ceiling [PI-HOW]. The Labyrinth paper found that dice tools
   *plus* state tools gave the best consistency. State tools alone made the model open new
   threads before it resolved old ones [LABYRINTH].

8. **Routine actions should skip the model.** In Narrative Engine, a travel press "moves one
   day, with no LLM call and no chat spam" [NE]. Hidden Door does not run typed text
   directly. It uses the text to regenerate the choice list [HD-BICKING]. Familiar shows
   player reactions as a "Cast / Pass" card [FAMILIAR]. AI Realm puts dice results into the
   text box and does not send them on its own [AIR-GUIDE]. For you: room-to-room movement,
   light and turn tracking should be engine actions, with optional short narration. Free
   text goes through the Referee and comes back as a proposal.

9. **Rulesets as data, with a code escape hatch, travel best.** Loreweaver defines a rule
   system in one YAML file with a small check-resolution language. Anything the language
   cannot express runs in a sandboxed script, "the engine rolls the dice first" [LW]. ink &
   bone's rulesets only define sheet fields, so the actual rules live in the prompt and "the
   AI rolls the dice" [INK]. That is the weaker design. Ironsworn tools share the Datasworn
   JSON data [IV] [TOMKIN]. Your Ruleset plugin should own resolution code. Generators can
   be pure data tables.

10. **Ground content before you narrate it.** Ian Bicking's review of Hidden Door says a
    chest had no fixed contents until the player read about it, so "choices change the past
    as well as the future" [HD-BICKING]. Intra had the same problem with a sound behind a
    door [INTRA]. FlexTale's prepless rolls help here. The engine should roll the room,
    exits and contents *before* the Referee describes the room, and pass those facts in.

11. **Expect yes-bias, and build failure into the engine.** Testers report "never failed a
    check" on EN World [ENWORLD]. Bicking saw "little real challenge" in Hidden Door
    [HD-BICKING]. ChatRPG v1 was "overly permissive" [CHATRPG]. Narrative Engine pre-rolls
    dice pools so the GM "uses real rolls rather than fabricating outcomes" [NE]. Engine
    dice plus OSE's own procedures (reaction, morale, wandering monsters) remove the
    Referee's chance to be kind.

12. **Test the Referee with a scripted model, and measure live runs separately.** Loreweaver
    runs 2,200+ offline tests with "a scripted Keeper and seeded dice". A nightly real-model
    run checks secret leaks and "dice-first misses" [LW]. Project Infinity drives its server
    tests with a scripted model [PI-HOW]. This matches the repo's `ScriptedDice` approach.

## Tool notes

### Friends & Fables (fables.gg), commercial

- **What it is.** A browser text RPG with an AI GM named Franz. It started as a Discord bot
  and became "more of a virtual tabletop for dynamic text RPGs" [FF-NEWCH]. The site claims
  100,000+ players, parties of up to 6, and 5e SRD-based combat [FF-HOME].
- **Layout.** Chat narration. A working-context drawer above the input [FF-FRANZ2]. A
  right sidebar holds turn order [FF-INPUT]. Battle maps with tokens; Franz "is also able to
  see your token and the monster tokens" [FF-DIVE]. A spell screen and a roll screen open
  from buttons [FF-PREP].
- **AI vs state.** Mixed, and it changed over time. Early combat ran in code. Combat V4
  gives Franz tools to roll, edit HP and edit turn order, and code still blocks spells
  without slots [FF-COMBAT4]. Movement is triggered by Franz from typed phrases such as "I
  travel 2 hours east". Franz "can only see the map size + character positions" [FF-TRAVEL].
- **Memory.** Franz updates a short "plot" and a "plan" after each message. Long-term
  memories form every five messages and are searched, not injected in full [FF-FRANZ2].
  Memories V2 made all old memories searchable through vector and text embeddings
  [FF-MEM2]. Franz turns player corrections into saved "instruction blocks" [FF-FRANZ2].
- **Notable ideas.** A visible context drawer with priority and expiry. Corrections become
  persistent instructions. A "Players Only" chat mode hidden from the GM. A Manual mode
  where Franz waits for a Continue press [FF-INPUT]. Suggested next actions [FF-SUGG]. A
  "trope reduction" list for repeated phrases such as "the scent of ozone" [FF-TRAVEL].
- **Complaints.** Users report wrong attack stats, roll problems and continuity issues
  (from search snippets of the feedback board; the posts are behind a login, so this is
  **unverified**) [FF-FEEDBACK]. The team's own combat notes list known gaps [FF-PREP]
  [FF-COMBAT4].

### AI Dungeon (Latitude), commercial

- **What it is.** A free-form AI story game. The docs say it does not track health,
  inventory or quests, because it is "a collaborative storytelling experience rather than a
  stat-based RPG" [AID-MEM].
- **Layout.** Story text with plot components (Plot Essentials, Author's Note, Story
  Summary) and Story Cards [AID-CONTEXT].
- **AI vs state.** All AI. No engine state.
- **Memory.** The best-documented system in this survey [AID-MEM]:
  - A Memory is a model summary of six actions. The latest six actions are never
    summarized.
  - Auto Summarization rewrites a Story Summary every 15 actions and compresses it when it
    grows.
  - The Memory Bank embeds each Memory and retrieves the top matches against the latest
    action. When full, it drops the least-used ones.
  - Story Cards load by trigger words, ranked by how recent and how frequent they are
    [AID-CONTEXT].
- **Notable ideas.** A documented context order and budget split [AID-CONTEXT]. The docs
  admit "Context length is a real, unavoidable constraint" [AID-MEM].
- **Complaints.** Triggered cards stop loading as history grows. Memories duplicate.
  Experienced users turn off auto-summary because it gets worse as the story grows
  [AID-REDDIT].

### Hidden Door, commercial

- **What it is.** A browser social role-play platform in licensed worlds (Pride and
  Prejudice, Wizard of Oz, The Crow, Call of Cthulhu). It launched in August 2025
  [HD-GB].
- **Layout.** Prose with a set of choices. Character, location, object and plot "cards"
  are visible. On-screen objectives [HD-BICKING]. The 2022 demo used word tiles and a card
  "tray" [HD-BLOG].
- **AI vs state.** Cards are the core state, and the narrator builds prompts from them
  [HD-BICKING]. Players can see "their current energy, their attributes, their location"
  [HD-GB]. Claims of a trope library of "tens of thousands" of entries come from a
  third-party guide and are **unverified**.
- **Memory.** Mostly the story text plus cards. Bicking found it inconsistent [HD-BICKING].
- **Notable ideas.** Typed text regenerates the choices instead of running directly.
  Character creation limits free text: "We don't let people type these in plain text"
  [HD-GB]. The CEO says a role-play tool "has to push back" [HD-GB].
- **Complaints** (Bicking's design review) [HD-BICKING]. Choices are ungrounded. Objectives
  appear and complete in the same moment. Failure is rare. Prose lingers on minor events.
  Latency makes play feel effortful.

### AI Realm (airealm.com), commercial

- **What it is.** An AI GM for 5e SRD (2014) adventures [AIR].
- **Layout.** Chat with a Notes panel that pins to the right on desktop. Tabs for NPC
  Cards, GM Guides, Character Data and a three-column character sheet [AIR-GUIDE].
- **AI vs state.** Mostly AI. Rules come from GM Guides that the AI is asked to follow.
  The AI edits notes through hidden instructions in its replies, and the UI shows a change
  notice [AIR-GUIDE].
- **Memory.** Toggleable NPC cards and guides. A gray (disabled) card "is hidden from AI
  but safely stored". An auto-updated Campaign Summary [AIR-GUIDE].
- **Notable ideas.** Clicking a stat rolls 3D dice. "Rolls are inserted into your chat
  textbox, not sent automatically" [AIR-GUIDE]. This keeps the player in control.
- **Complaints.** I found none in primary sources.

### Intra (Ian Bicking), open source experiment

- **What it is.** A hackathon text adventure. The source is at github.com/ianb/intra-game
  [INTRA].
- **Layout.** Plain text with no Markdown, because Markdown makes it feel like a chatbot.
  A Graphviz map [INTRA].
- **AI vs state.** Code holds location, exits, locks and NPCs. Player text is first parsed
  into intents. The model changes state only through explicit tags. The author used tags
  instead of tool calls because tool use made models "less creative" [INTRA].
- **Memory.** The time-ordered event log with no summaries, filtered per NPC [INTRA].
- **Notable ideas.** "In a game the 'user' is the game engine, not the player." Use the
  same names for ids and display titles. A guided list of questions for resolution (is it
  possible, what happens on success or failure) [INTRA].
- **Complaints** (the author's own). Fixation on early ideas. The model always responds.
  It invents objects too easily. Easy to prompt-hack [INTRA].

### Iron Vault (Obsidian plugin), open source, 111 stars

- **What it is.** A gameplay tool and virtual tabletop for Ironsworn, Delve, Starforged
  and Sundered Isles inside Obsidian. It uses Datasworn data [IV].
- **Layout.** Journal notes in the main pane. A right sidebar with Moves, Oracles and the
  Character Sheet [IV].
- **AI vs state.** No AI. Commands make moves and create tracks. It is not a "play for
  me" tool: the player resolves rules [IV].
- **Memory.** The journal is plain Markdown with mechanics blocks [IV-MECH].
- **Notable ideas.** Mechanics blocks in KDL with nodes for `move`, `roll`, `progress`,
  `meter`, `clock`, `oracle` and more. They render as cards and stay machine-readable
  [IV-MECH]. Homebrew loads from Datasworn or Markdown [IV]. This is a good model for your
  Ironsworn Ruleset's log format.
- **Complaints.** None researched.

### Other Ironsworn and Starforged companions, mostly free

- Tomkin Press lists Iron Journal / Stargazer (browser, local storage), Pocketforge (offline
  PWA, prints an HTML journal), Iron Fellowship / Crew Link / Iron Link (sync; roll results
  go into session logs), the Foundry module, and Iron Vault. It notes that none of them use
  generative AI [TOMKIN].
- The shared lesson is data. Datasworn and Dataforged provide "organized reference data (in
  JSON format)" for moves, assets and oracles [TOMKIN].

### PUM Companion, commercial

- **What it is.** The official app for the Plot Unfolding Machine solo system [PUM].
- **Layout.** Themed panels that expand on large screens. One log for events, rolls and
  notes [PUM].
- **AI vs state.** The core app has no AI and runs offline. An "AI Assistant" is a separate
  paid add-on [PUM].
- **Notable ideas.** 50+ oracles, "a click" each. A plot track advanced by Scene Beats.
  Custom oracles [PUM].

### Mythic GME Adventures, open source, 31 stars

- **What it is.** An app for Mythic GME 2e: fate chart, meaning tables, threads and
  characters lists, scenes, keyed scenes [MGA].
- **Layout.** On a phone: Oracles, Scenes and More sections. On desktop the active lists sit
  at the top [MGA-MANUAL].
- **Notable ideas.** Active lists with counters, which mirror the book. A roll log. A
  physical-dice mode where you roll yourself and look up the result [MGA]. These are
  useful UI patterns for your Mythic Generator plugin.

### Foundry VTT AI modules

- **Loremaster** (paid). Claude in Foundry through a proxy. GMs can override with
  "[GM RULING: ...]" and choose whether a ruling lasts for the session or persists. You
  can upload an adventure PDF and core rules [LOREMASTER]. The page says nothing about
  summaries or retrieval.
- **Familiar.** An AI co-pilot that "never invents the story". A rules engine checks each
  5e attack, spell and move and "refuses illegal actions with a reason". Every world change
  passes through the GM's client. Risky actions wait for approval. Player reactions show as
  a "Cast / Pass" card. The AI cannot write script code. Rules that are not modelled are
  "flagged for you to decide" [FAMILIAR]. This is the closest match to your
  propose-then-confirm design.
- **Simulacrum, FoundryAI and others.** Search listings describe tool-calling copilots.
  The Simulacrum package page now returns 404, so details are **unverified**.

### SillyTavern RPG Companion, open source, 337 stars

- **What it is.** A SillyTavern extension that tracks stats, inventory, quests and scene
  info in a side panel. It is now deprecated in favour of the author's Marinara Engine
  [STRPG].
- **Layout.** A panel left or right of the chat. Info-box widgets for date, weather and
  location. A present-characters panel [STRPG].
- **AI vs state.** The model generates the tracker data, in the same reply ("Together") or
  in a separate call ("Separate"). The data is stored per swipe [STRPG].
- **Lesson.** Panels are popular, but if the model writes them, they inherit the model's
  errors.

### Narrative Engine (NarrativeEngine-P), open source, 135 stars

- **What it is.** A self-hosted AI GM for any OpenAI-compatible model or Ollama. Browser UI.
  It has a frozen mod API in 2.0 [NE].
- **Layout.** Story on the right, a campaign drawer on the left. A composer toolbar with
  Deep Search, Dice, Inject Event, Travel and Ask GM. A token gauge. A pixel-art world map
  extension (marked work in progress) [NE].
- **AI vs state.** The model narrates. The engine pre-rolls d20 pools for seven skill
  types and offers a `roll_dice` tool. NPC goals, world arcs and event engines run on
  dice in the background [NE].
- **Memory.** A lossless verbatim archive. Two-stage retrieval: pick chapters from
  overviews, then fetch scenes by local embeddings, injected verbatim. Older turns can be
  condensed, but the last 8 messages stay verbatim, and "dice rolls, HP/MP values, and all
  proper names are preserved exactly". Pinned passages. A "Divergence Register" of facts
  extracted after each turn [NE].
- **Notable ideas.** Travel as an engine action with no LLM call. Scene rollback that
  reverts world state. Per-module token caps [NE].

### Project Infinity, open source, 48 stars

- **What it is.** A browser 5e SRD 5.1 RPG with an AI GM that "rolls real dice, tracks real
  stats" [PI-README].
- **Layout.** Transcript with streamed prose. An engine-written Mechanics panel after each
  turn. A combat bar above the transcript with initiative, HP and conditions. A sidebar
  character sheet. A Tools toggle that shows full tool results [PI-README] [PI-HOW].
- **AI vs state.** A local MCP server with SQLite owns state. The GM sends all tool calls
  in one batch, waits, then writes prose. The engine owns the "mechanical skeleton". The
  docs list, by design, what the GM still decides (timing, action economy, cover, turn
  order). A build gate stops that list from growing quietly [PI-HOW].
- **Memory.** A lean character sheet injected each turn, without the numbers the GM must
  not invent. A STATE page (goal, hooks, clocks, debts, secrets) plus compacted events and
  recent entries kept verbatim. A known-places tree capped at 12 places [PI-HOW].
- **Notable ideas.** "The engine guarantees the beat": if no prose arrives, the engine
  asks once more. A token budget gate in CI. Tool results projected to only the needed
  keys [PI-HOW]. If the GM misses an update, the player tells it, "exactly as you would a
  human DM" [PI-README].

### Loreweaver, open source, 71 stars

- **What it is.** An engine and open standard for AI-run tabletop RPGs. Ships CoC 7e and
  D&D 5e SRD. Desktop and terminal clients [LW].
- **Layout.** A Markdown narrative log, colour-coded dice, live character, party and
  variable panels. Modules can declare their own panels. The server decides who sees each
  panel [LW].
- **AI vs state.** Four actors. The Keeper model narrates. The engine owns dice, sheets,
  clocks, trackers and permissions. A small Scribe model reconciles the ledger against the
  narration and only proposes. A Director model handles handouts with a player's-eye view
  [LW].
- **Memory.** Chronicle documents. Past 60% of context, the oldest records fold into a
  running summary until usage is under 40%. The last four turns never fold. Folded records
  stay in a search index [LW].
- **Notable ideas.** Rule systems as YAML with a resolution DSL. Sandboxed scripts that
  get dice from the engine. One `project(document, viewer)` filter for every outbound
  surface, which keeps secrets out of player views [LW]. Relevant to keeping FlexTale and
  module secrets out of the player UI.
- **Honest status.** The author says the deterministic half is solid and live model
  behaviour is "measured, not proven" [LW].

### ink & bone, open source, 1 star

- **What it is.** A local Go and React AI GM app that claims 13 or 14 systems, Ironsworn
  among them [INK].
- **Layout.** Left sidebar: portrait, editable sheet fields, dice buttons, dice history.
  Centre: transcript, combat strip, input bar, map drawer. Right tabs: Notes, Journal,
  NPCs, Objectives, Items [INK].
- **AI vs state.** A ruleset is a JSON list of sheet fields. "The AI rolls the dice."
  Background jobs extract NPCs, stats and items after each GM turn [INK].
- **Memory.** Full session history plus a recap regenerated every 4 GM messages, and
  keyword-searched rulebook chunks [INK].
- **Lesson.** A system-agnostic sheet without engine-owned resolution puts the rules back
  in the prompt. That is the failure you want to avoid.

### rpg-mcp (mnehmos.rpg.mcp), open source, 47 stars

- **What it is.** An MCP server that gives any MCP client a 5e-style engine: combat,
  slots, inventory, quests [MCP].
- **AI vs state.** "The AI can't just decide you hit or miss" [MCP].
- **Notable ideas.** Consolidated action-enum tools with fuzzy matching and "guiding
  errors". The 195 to 36 tool cut and its token savings [MCP].

### Not verified or out of scope

- **Infinite Worlds** (infiniteworlds.app). The site returned an app error, and search
  found no primary docs. All claims about it are **unverified**, so it is not compared.
- **Character.ai and similar chat apps.** These are character chat, not rules harnesses.
  Not researched.
- **RPG-OS** (9 stars) keeps campaign state in readable files for a file-capable agent. It
  is close to this repo's current terminal approach [RPGOS]. Not researched further.

## Research papers

- **FIREBALL** (Zhu et al., 2023). Nearly 25,000 D&D combat sessions from the Avrae bot
  with structured state. Utterance-to-command pass rate was 0.726 with state and 0.235
  without. Failure modes: narrating actions for player characters, calling any damage a
  kill, inventing names when state is missing [FIREBALL].
- **Labyrinth function calling** (Song, Zhu, Callison-Burch, 2024). Dice functions plus
  state functions scored best on consistency (4.388). Without a dice function, play stalls
  in a "dice roll deadlock". State functions alone open new state "before resolving the
  previous challenges" [LABYRINTH].
- **ChatRPG, static vs agentic** (Jørgensen et al., CUI 2025). A Narrator agent plus an
  Archivist agent beat one long prompt on 9 of 14 measures (N=12). v1 forgot items and was
  "overly permissive". v2 was sensitive to tool description wording [CHATRPG].
- **World-state transformations** (Góngora et al., 2026). The model only selects which
  pre-written transformation a free-text input triggers. A symbolic module runs it after
  checks. Errors remained, such as wrong puzzle answers accepted. A fixed order caused
  planning errors [WST]. This is close to your proposal-card design.
- **D&D as a dialog challenge** (Callison-Burch et al., EMNLP 2022). A fine-tuned state
  tracker reached 58% joint accuracy [DND-DIALOG].
