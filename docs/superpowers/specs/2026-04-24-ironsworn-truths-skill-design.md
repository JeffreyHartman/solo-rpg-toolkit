# Ironsworn Truths Skill — Design Spec

**Date:** 2026-04-24
**Sub-project:** Datasworn ingestion (first feature)
**Goal:** A standalone Claude Code skill that walks the player through locking in the 11 Ironsworn setting truths at the start of a campaign, saving each as a structured note in the player's Obsidian vault and surfacing locked answers to every future session via the campaign's `CLAUDE.md`.

---

## Motivation

Ironsworn ships 11 setting truths (Old World, Iron, Legacies, Communities, Leaders, Defense, Mysticism, Religion, Firstborn, Beasts, Horrors). Each has 3 d100-weighted options and a quest starter. They are meant to be agreed-upon at session zero, then act as load-bearing setting facts for the rest of the campaign.

Today, the Ironsworn skill in this toolkit assumes the player has already done this off-camera. There is no in-toolkit workflow for it. Players who want to actually use the truths system have to read the rulebook, transcribe answers manually, and remember to keep them in front of the LLM.

This skill closes that gap. It also serves as the first proof of concept for ingesting the `@datasworn/ironsworn-classic` JSON dataset (saved at `reference/datasworn-ironsworn-classic/`, CC-BY-4.0) into shippable skill content.

---

## Scope

**In scope:**
- New skill `skills/ironsworn-truths/` — markdown only, walks user through locking 11 truths
- Conversion of `truths` section from `classic.json` into one markdown reference file inside the skill
- Output schema for locked truths in the player's Obsidian vault (`Lore/Truths/`): one file per truth
- Frontmatter-based progress tracking (`locked: true|false`)
- Summary block injection into the campaign's `CLAUDE.md`
- Soft hook from existing `ironsworn` skill ("truths not locked — want to set them up?")
- A reusable conversion script `scripts/datasworn_to_truths.py` so the skill content can be regenerated if datasworn updates

**Out of scope:**
- Other datasworn sections (oracles, moves, assets) — separate sub-projects
- Editing/migrating truths once locked (user re-runs skill on a single truth)
- Vow management (a quest seed adopted as a vow is referenced from the vow file, not migrated)
- Mythic 2e meaning-pair generation logic — relies on existing `solo-roll meaning-pair` and `mythic-gme` skill if loaded
- Auto-loading of one skill from another — the existing `ironsworn` skill only **suggests**, never auto-activates

## Architecture

```
skills/ironsworn-truths/
  SKILL.md            # workflow + activation rules
  truths.md           # all 11 truths with 3 stock options + quest starters (converted from datasworn)

scripts/
  datasworn_to_truths.py   # one-shot generator: reads classic.json -> writes truths.md

<player-vault>/Lore/Truths/
  old-world.md
  iron.md
  legacies.md
  communities.md
  leaders.md
  defense.md
  mysticism.md
  religion.md
  firstborn.md
  beasts.md
  horrors.md

<campaign>/CLAUDE.md
  ## Setting Truths       # appended/regenerated by the skill on each lock
  - **Old World**: <one-line summary of locked answer>
  - **Iron**: <one-line summary>
  ...
```

Pure markdown skill. No new Python module, no new `solo-roll` subcommand. The skill leans on existing CLIs (`solo-roll roll 1d100`, `solo-roll meaning-pair`) when the user wants randomization or inspiration mid-decision.

## Components

### `skills/ironsworn-truths/SKILL.md`

Frontmatter:
```yaml
---
name: ironsworn-truths
description: Use when starting a new Ironsworn campaign and the player wants to lock in the 11 setting truths (Old World, Iron, Legacies, Communities, Leaders, Defense, Mysticism, Religion, Firstborn, Beasts, Horrors). Activates on phrases like "set up truths", "session zero", "establish my Ironsworn world", or when the ironsworn skill notices truths are not yet locked. Walks the player through each truth one at a time, supports picking a stock option, rolling d100, generating fresh options, or shaping the player's own world idea, and saves locked answers to the player's Obsidian vault plus a summary block in the campaign CLAUDE.md.
---
```

Body sections:
1. **Activation guard** — first action: scan `<player-vault>/Lore/Truths/`, list which of the 11 are locked, ask user how to proceed (continue with first unlocked, jump to a specific truth, revisit a locked one, exit).
2. **Per-truth loop** — present truth name + stock options + quest starter from `truths.md`. Offer five paths: pick stock 1/2/3, roll d100 against the dice ranges, ask LLM to generate fresh options grounded in setting tone, riff on a player-provided idea, or freeform-write the answer. Iterate over multiple turns until user says lock.
3. **Lock procedure** — write/update the per-truth file in `<player-vault>/Lore/Truths/<slug>.md` with frontmatter `locked: true`, locked answer, optional quest seed, optional notes. Then regenerate the `## Setting Truths` block in the campaign `CLAUDE.md` (replace existing block; append if absent).
4. **Mythic 2e graceful coupling** — if `mythic-gme` skill appears loaded, mention `solo-roll meaning-pair` as an inspiration option when the user is stuck. Never assume it is loaded.
5. **Path resolution** — read `<campaign>/CLAUDE.md` for `PLAYER_VAULT_PATH` (the convention solo-campaign already established). Truths land at `<vault>/Lore/Truths/`.
6. **Re-entry** — running the skill again on a locked truth offers "edit", "replace", or "view". Edit preserves the lock; replace clears the file and restarts that truth's loop.

### `skills/ironsworn-truelookths/truths.md`

A single markdown reference file generated from datasworn. For each of the 11 truths:

```markdown
## Iron
**Source:** Ironsworn Rulebook (Shawn Tomkin, CC-BY-4.0). Datasworn id `classic/truths/iron`.

### Option A (1–33)
<description prose from datasworn `description`>

**Quest seed:** <quest_starter prose>

### Option B (34–67)
...

### Option C (68–100)
...
```

CC-BY-4.0 attribution lives at the top of the file.

### Per-truth output file (player vault)

```markdown
---
locked: true
truth: iron
source: classic/truths/iron
chosen_option: B           # or "custom"
---

# Iron

<one-paragraph locked answer in the player's voice>

## Quest seed

<quest seed prose, optional, may be empty if user opted out>

## Notes

<freeform notes the player added during setup, optional>
```

The `chosen_option` field is a hint, not a constraint — it tells future re-entry which stock option (if any) the locked answer was based on. `custom` means the user wrote freeform.

### Campaign `CLAUDE.md` summary block

The skill maintains a fenced block:

```markdown
<!-- BEGIN: ironsworn-truths-summary -->
## Setting Truths

- **Old World**: <one-line summary>
- **Iron**: <one-line summary>
- **Legacies**: <one-line summary>
- **Communities**: <one-line summary>
- **Leaders**: <one-line summary>
- **Defense**: <one-line summary>
- **Mysticism**: <one-line summary>
- **Religion**: <one-line summary>
- **Firstborn**: <one-line summary>
- **Beasts**: <one-line summary>
- **Horrors**: <one-line summary>

(Full prose: `<vault>/Lore/Truths/`. Re-run `ironsworn-truths` skill to revise.)
<!-- END: ironsworn-truths-summary -->
```

The HTML comment fences let the skill find and replace the block idempotently. Unlocked truths render as `_(not yet locked)_` so the block is always 11 lines.

### `scripts/datasworn_to_truths.py`

A small one-shot generator. Inputs:
- `--datasworn` path to `classic.json` (default: `reference/datasworn-ironsworn-classic/json/classic.json`)
- `--out` path to `skills/ironsworn-truths/truths.md`

Walks `data["truths"]`, emits the markdown structure above. Idempotent — running twice produces identical output. Fails fast if `truths` is missing or empty. No coupling to the rest of `solo_roll`; pure stdlib.

The script is committed so the conversion is reproducible. It is **not** part of the runtime — the skill ships the generated markdown directly.

## Data flow

1. User starts campaign via `solo-campaign foo <path>`. Existing flow scaffolds `dm-notes/`, `CLAUDE.md`, etc.
2. User opens Claude in the campaign dir. Mentions Ironsworn → `ironsworn` skill activates → notices `<vault>/Lore/Truths/` is empty → suggests loading `ironsworn-truths` skill.
3. User loads `ironsworn-truths` skill → it scans the truths dir, reports `0 of 11 locked`, asks where to start.
4. User picks Old World. Skill reads `truths.md` for Old World content, presents options. User picks Option B → "lock it." Skill writes `<vault>/Lore/Truths/old-world.md` with `locked: true`, regenerates the summary block in campaign `CLAUDE.md`.
5. Repeat per truth. Multi-turn refinement allowed per truth (skill stays in the loop until user says lock).
6. Future sessions: ironsworn skill activates → sees truths locked → no nudge. Campaign `CLAUDE.md` is auto-loaded so the LLM has all 11 locked summaries in context. For deep references (a quest seed the player wants to adopt), LLM reads the full file from the vault.

## Error handling

- **Vault path not configured** — campaign `CLAUDE.md` is missing `PLAYER_VAULT_PATH`. Skill explains, asks user to add it, exits.
- **Vault dir does not exist** — skill creates `<vault>/Lore/Truths/` on first lock. If the vault root itself is missing, error and stop.
- **Truths reference file missing from skill** — should never happen (ships with skill). If it does, error and tell user to reinstall.
- **Datasworn JSON missing during conversion script run** — script errors with the path it tried, exits non-zero.
- **Existing locked file with different `chosen_option`** — re-entry asks user "edit" / "replace" / "view" before touching the file.

## Testing

The skill itself is markdown — no automated tests in the usual sense. Two pieces are testable:

1. **`scripts/datasworn_to_truths.py`** — pytest unit tests in `tests/test_datasworn_to_truths.py`. Use a tmp_path fixture with a small synthetic datasworn-shaped JSON (one truth, two options) and assert the generated markdown matches expected structure. Don't test against the real 660 KB file — too brittle, and the production output is committed already.
2. **End-to-end smoke check** — manual: run the conversion script against the real `classic.json`, diff against the committed `skills/ironsworn-truths/truths.md`. Should be zero diff. Documented in the skill's README/notes, not automated.

The skill behavior (per-truth loop, lock procedure, summary block regeneration) is exercised through play and is not unit-testable.

## Open questions / deferred decisions

- **Truth re-locking workflow** — current design says re-entry on a locked truth offers edit/replace/view. The exact prompt wording and how aggressively the skill warns about replacing a load-bearing truth (campaigns build on these) can be refined during implementation.
- **Empty quest seed** — some users may not want quest seeds at all. The output format already makes the section optional; the skill workflow needs to ask explicitly rather than assume.
- **Multi-vault / re-pointing** — if the player moves their vault, locked-truth files do not auto-follow. Out of scope here; the existing `solo-campaign` flow has the same limitation.
