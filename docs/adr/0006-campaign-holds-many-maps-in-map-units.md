# A campaign holds many maps, each on its own plane in map units

A campaign holds many maps in `state["maps"]`, keyed by map id, and `state["active_map"]` names the map that the party is on. The engine stores every map. Generators, modules, and the Referee only supply content. We chose this over a map that each generator owns because a staircase, a town, and a pre-written adventure all need maps that no one generator made, and the Referee controls the world (ADR 0003). Positions are in map units with a grid scale, not in image pixels, because Foundry measures in pixels and a change of image resolution or grid size then misaligns everything on the map. Fog is one state per area, not a raster, because level B reveals by area and has no vision.

## Consequences

- **Content sources.** A generator declares `make` procedures (they return a whole map) and `grow` procedures (they add to a map, as FlexTale `explore` does), or both. A module loads ready-made maps. The Referee decides when a new map comes into the world. Each map records its `source`: `generator`, `module`, or `referee`, plus the plugin name.
- **Coordinates.** Each map has a `grid` with `type` (`square` or `none`, `hex` later), `size` (map units per grid space), `distance`, and `units`. A gridless map keeps the scale. A `background` is `none` (the UI draws a styled render from area shapes) or an image placed by a rectangle in map units. The phase 7 grid reads the same points, so the save format does not change.
- **Areas.** An area has a `shape`: a list of rectangles and polygons. An image map can give an area a mask file, which is render data only. Area ids are unique inside their map. A reference across maps uses the pair (map id, area id).
- **Fog.** An area is `hidden`, `known`, or `explored`. `visible` is not stored: it is the area that holds the party token, so a later vision system can change how it is derived. A map is `hidden` or `known`. The player sees only known maps and the maps that the party went to. A link to a hidden map shows only its own label.
- **Links.** A link is a one-way area feature with a label and a target (map id, area id). Taking it is the party token move that the engine owns (ADR 0005). The move switches `active_map`, puts the party token in the target area, and sets that area to `explored`. It raises a wake if the area was not explored before. A link with no target raises a wake, and the Referee makes the map and sets the target. A return link is a second link.
- **Campaign state and map state.** The turn clock, light, and combat are campaign state, and combat names its map. A move to another map does not reset the clock. Each map has a `facts` dict, for example `dungeon_level` and wandering-check settings. A plugin declares each fact key that it reads, with a default. Procedures read facts from the active map. Plugin-only data goes in `map.plugins[<plugin name>]`, for example FlexTale `open_exits`.
- **Tokens.** Tokens live on their map as `{kind, ref, area, x, y}`, with `kind` `party`, `monster`, or `npc`. In phase 2 the whole party has one token, and that token is the one store of the party position. The keys `art` and `conditions` are reserved for later phases. The player sees a monster or NPC token only in the visible area.
- **Old campaigns.** On load, the engine upgrades a campaign with one `state["map"]` once. It becomes the map `level-1` with `dungeon_level: 1`, a gridless scale, and source FlexTale. `known: true` becomes `explored`, `x, y, w, h` becomes a rectangle shape, and `party.area` becomes the party token. `state.json` gets a `version`, and the engine keeps the old file as `state.v1.json`.
