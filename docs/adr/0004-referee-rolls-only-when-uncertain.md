# The Referee rolls only when the outcome is uncertain

The Referee runs the world as a human GM would. When the outcome is obvious, it decides and acts with no table and no roll: a cornered goblin attacks, a shopkeeper sells a torch, a frightened NPC runs. When the outcome is uncertain, it uses a procedure if one exists, so that the dice give the result weight. When the outcome is uncertain and no procedure covers it, the Referee makes the change through generic engine tools, and the engine rolls if a roll is needed. Procedures and tables exist to add randomness and weight, not to gate play, so a missing table never stops the game. We chose this because the first playtest ended when the torch burned out and the Referee had no tool to add one, and because a procedure for every case makes the Referee slower and less sensible than a human GM.

## Consequences

- The engine still owns all state and all dice (ADR 0001). A Referee edit goes through an engine tool, and any roll in it uses the engine's dice.
- The rule covers the world, as ADR 0003 defines it. The player's own choices and judgment calls stay with the player.
- Each Referee edit shows a mechanics card with what changed and why, so the player sees it and can dispute it.
- A gap in the plugins is not a blocker. For example, in a campaign where no plugin answers a monster's turn, the Referee picks the monster's action.
