# The Referee acts directly when no procedure covers a need

When no procedure covers what the game needs, the Referee makes the change itself through generic engine tools, as a human GM would: it adds a torch to a sheet, picks a monster's action, or applies damage. Procedures and tables exist to add randomness and weight, not to gate play, so a missing procedure never stops the game. We chose this because the first playtest ended when the torch burned out and the Referee had no tool to add one, and because building a procedure for every gap before play can continue does not scale.

## Consequences

- The engine still owns all state and all dice (ADR 0001). A Referee edit goes through an engine tool, and any roll in it uses the engine's dice.
- A procedure wins when one exists. The Referee guide tells the Referee to use the procedure first and an edit only when none fits.
- Each Referee edit shows a mechanics card with what changed and why, so the player sees it and can dispute it.
- Default behavior fills plugin gaps. For example, in a campaign where no plugin answers a monster's turn, the Referee picks the monster's action.
